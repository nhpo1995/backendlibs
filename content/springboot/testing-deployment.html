Đưa bằng chứng đi cùng artifact

API danh bạ trả 400 cho tên nhóm rỗng. Nếu test chỉ nhìn status thì liệu biết dữ liệu đã được giữ nguyên? Nếu H2 xanh, kiểm gì trước khi dùng cùng bản build với PostgreSQL? Bài này nối hợp đồng lỗi, giao dịch và test biên HTTP.

Test phải trả lời một câu hỏi cụ thể

“API trả 400” và “request lỗi không tạo dữ liệu” là hai kết luận khác nhau. Một implementation có thể insert rồi mới kiểm tra tên, sau đó trả 400. Test chỉ assert status sẽ bỏ sót lỗi. Hãy nêu invariant trước: dữ liệu sai không được lưu; reader không ghi được; thay membership có ID thiếu phải giữ trạng thái cũ.

@SpringBootTest có thể nạp context đầy đủ; mặc định không đồng nghĩa server thật được mở cổng. Dùng RANDOM_PORT và client HTTP khi muốn kiểm tra luồng mạng. Test slice giúp tập trung nhanh nhưng phải biết phần nào được thay bằng mock.

Không để test security che mất điều cần chứng minh

Các helper đến từ spring-security-test. User mock cấp danh tính cho request, không kiểm password encoder/provider. Dùng httpBasic khi câu hỏi là credential thật được chấp nhận hay từ chối. Với request không an toàn, thiếu CSRF có thể làm test nhận 403 trước policy; thêm token hợp lệ để cô lập bài test authorization.

Test rollback ở service không nên vô tình được transaction của test bao bọc, vì cleanup cuối test có thể che việc service không rollback. Đọc dữ liệu trước/sau ở ranh giới rõ ràng. Khởi tạo dữ liệu độc lập cho mỗi test; không dựa vào thứ tự chạy hoặc ID tự tăng luôn bằng 1.

Thực hành có starter và lời giải riêng

Đọc assertion thất bại và sửa implementation; không sửa expected cho khớp code sai. Sau khi từng mốc đạt, chạy cả suite để phát hiện regression. Các đề mở rộng JPA/account/OAuth2 còn cần test riêng; suite starter không tự chấm mọi ví dụ của giáo trình.

O1 · kiểm contract trên PostgreSQL 16

Starter. Copy project Spring Foundations bạn đã hoàn thành. Baseline của starter dùng H2 và seed Backend, Ops. Với ca DB mục tiêu, bổ sung driver PostgreSQL, Flyway PostgreSQL và thư viện test Testcontainers PostgreSQL theo BOM đang dùng. Dùng Docker, khai báo image cố định ví dụ postgres:16.6 cho lab và ghi tag hoặc digest thật đã chạy. Dùng profile riêng cấu hình URL cùng credential qua biến môi trường. Tách seed học tập khỏi migration chạy ở môi trường thật.

Trong test tích hợp, đăng ký PostgreSQLContainer qua @ServiceConnection với dependency spring-boot-testcontainers, hoặc đăng ký URL/user/password bằng @DynamicPropertySource. Chỉ dùng một cơ chế migration cho profile DB mục tiêu, tắt script init cũ. Với JPA, dùng ddl-auto=validate khi đã có schema do migration quản lý. Dùng setup test để tạo Backend và Ops nếu môi trường không tự seed.

Chạy và nộp. Sau khi bổ sung test DB, chạy mvn -f practice/spring-foundations/starter/pom.xml verify trong bản làm của bạn (đăng ký integration test vào lifecycle Maven nếu dùng Failsafe). Dùng JAR từ chính lượt build để khởi động trên DB lab, ghi checksum của JAR, phiên bản DB, kết quả migration và lặp ca POST/GET thật. Các test H2 vẫn dùng để phản hồi nhanh; ghi riêng kết quả chạy PostgreSQL vì ca dialect và đồng thời phụ thuộc DB. Repo hiện có starter H2; phần PostgreSQL là triển khai cần tự làm.

Chỉ một test MockMvc xanh nhưng DB vẫn có thêm hàng. Test nào bắt được?

Giữ app và repository thật, gọi request rồi đọc lại bằng một truy vấn độc lập. Nếu lỗi phụ thuộc dispatch hoặc profile DB, thêm kiểm qua HTTP trên artifact và DB mục tiêu.

Từ chạy local đến vận hành

Build một artifact rõ phiên bản; truyền cấu hình theo môi trường, không commit credential. Dùng migration schema có review cho DB lưu bền. Health endpoint phản ánh điều kiện sức khỏe được cấu hình, không phải bằng chứng mọi use case đúng. Readiness và liveness cần tiêu chí phù hợp với cách triển khai.

Actuator cần dependency và chính sách expose/access rõ ràng. Mở mọi endpoint như env/configprops ra Internet có thể lộ thông tin vận hành. Với SecurityFilterChain tự viết, kiểm tra lại policy Actuator thay vì giả định Boot vẫn bảo vệ như cấu hình mặc định.

Log cần thời điểm, request/correlation ID và dấu hiệu đủ để nối các sự kiện. Không log password, Authorization, token hoặc dữ liệu cá nhân tùy tiện. Một log “created” trước commit không chứng minh giao dịch đã thành công; đối chiếu response và trạng thái dữ liệu.

Bài gỡ lỗi: test xanh nhưng chạy thật sai

  1. Kiểm tra test có mock đúng thành phần đang gây lỗi không.
  2. So profile, DB, artifact và dependency giữa test và tiến trình thật.
  3. Tái hiện request tối thiểu; so status, header, body và SQL.
  4. Thêm test ở tầng có thể bắt lỗi, rồi xác nhận test thất bại trước khi sửa.
  5. Chạy test và request thật sau sửa; ghi giới hạn môi trường đã kiểm tra.
Cần bao nhiêu test để đủ?

Không có con số chung. Chọn các invariant, biên đầu vào và đường lỗi có hậu quả thực tế; tránh test chỉ lặp từng dòng implementation hoặc chỉ kiểm “context loads”.
