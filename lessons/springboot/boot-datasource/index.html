Mục tiêu và điều kiện học

Cấu hình datasource bằng biến môi trường và kiểm tra sai URL/sai schema riêng.

Cần biết trước: HTTP, Maven và cấu hình Spring Boot. Các bài ứng dụng có thể cần đọc trước phần dữ liệu tương ứng; dùng lộ trình để chọn kiến thức còn thiếu.

Baseline: Java 17 · Spring Boot 3.5.10 · Framework 6.2 · Security 6.5. Mỗi demo có hướng dẫn riêng; ví dụ H2 không chứng minh hành vi trên DB khác.

Phân biệt lỗi kết nối và lỗi schema

Web server có thể sẵn sàng nhận HTTP nhưng truy vấn danh bạ vẫn thất bại vì thiếu bảng. Dựa vào cấu hình có hiệu lực, lần từ URL JDBC và credential tới driver, pool, rồi schema. Chọn DB học tập riêng cho các ca đổi cấu hình.

Với solution Spring Foundations dùng H2, schema.sql và data.sql được thực thi khi Boot khởi tạo DB. Khi tắt init bằng --spring.sql.init.mode=never trên một lần chạy mới, app có thể khởi động nhưng đọc nhóm báo lỗi vì schema rỗng. Nếu URL dùng giao thức không có driver tương ứng, lỗi xảy ra trước khi chạy câu SELECT.

Tự kiểm trên web. Chọn dòng ứng với ca tắt SQL init. Dự đoán cấu hình nào cần đổi rồi đối chiếu với sơ đồ. Sai schema và cạn pool có thể cùng thành lỗi 5xx nhưng cần bằng chứng khác nhau.

Thực hành cục bộ. Từ thư mục giải nén, chạy mvn -f practice/spring-foundations/solution/pom.xml package. So ba lần khởi động riêng của practice/spring-foundations/solution/target/spring-foundations-1.0.0.jar: mặc định, thêm --spring.sql.init.mode=never, rồi quay lại mặc định. Gọi curl.exe -i -u reader:demo-pass http://127.0.0.1:8181/api/groups sau mỗi lần. Ghi có kết nối được hay không, status, nguyên nhân JDBC sâu nhất ở ca lỗi và JSON Backend/Ops ở lần cuối. Sau đó viết test smoke gọi JdbcTemplate và đọc nhóm từ đúng DB trước khi viết test controller. Phần MySQL dưới đây là mô hình product riêng.

Chạy các ví dụ trên máy

Tải bộ demo Maven (.zip). Giải nén và dùng thư mục spring-demo-bundle chứa lessons và practice làm thư mục gốc cho các lệnh trong bài. Khi bài yêu cầu vào thư mục demo, mở thư mục chứa pom.xml của demo đó.

Kết nối MySQL

Khi ứng dụng có JPA và cần dùng MySQL, Spring Boot phải tạo DataSource để Hibernate lấy kết nối. Nếu thiếu JDBC URL và không có CSDL nhúng phù hợp trên classpath, bạn có thể gặp Failed to configure a DataSource ngay lúc khởi động. Để kết nối MySQL, cần MySQL Connector/J, JDBC URL chỉ tới schema đích và tài khoản được cấp quyền.

Tạo schema và bảng

Dùng IntelliJ Database, MySQL CLI hoặc Workbench để chạy SQL tạo bảng và kiểm tra dữ liệu. Kết nối thử thành công trong IDE chỉ xác nhận thông số của IDE. Spring Boot dùng cấu hình spring.datasource riêng, nên cần kiểm tra hai bên cùng trỏ tới đúng schema.

Schema của ví dụ là product. Bảng product_offerings dùng id làm khóa chính tự tăng, name bắt buộc, price lưu số nguyên VNĐ và color lưu tên màu. Demo dùng BIGINT để khớp Long trong entity.

Cấu hình datasource và cổng HTTP

Spring Boot đọc application.yaml hoặc application.properties từ src/main/resources. Hai định dạng biểu diễn cùng bộ thuộc tính. YAML nhóm theo cấp, còn Properties dùng khóa như spring.datasource.url. Căn lề YAML bằng dấu cách.

localhost:3306 là địa chỉ MySQL trong URL JDBC. localhost:811 là địa chỉ HTTP của demo. Spring Boot thường dùng 8080 khi để cổng mặc định. Nếu 8080 đang bị chiếm, đặt server.port: 811 và đổi URL gọi API sang cổng mới. Khi chạy MySQL cổng khác, sửa DB_URL theo đúng cổng.

Demo dùng ddl-auto: validate để kiểm tra bảng đã chuẩn bị sẵn. Chạy SQL khởi tạo trước khi khởi động ứng dụng.

Nếu log báo không nạp được driver class, mở pom.xml và kiểm tra MySQL Connector/J đã có trong classpath sau khi Maven tải dependencies. Với URL jdbc:mysql:, Spring Boot có thể suy ra driver từ URL khi connector đã có sẵn.

SQL tạo bảng SQL tạo dữ liệu mẫu Cấu hình YAML đầy đủ

JDBC URL, driver và connection pool

Đọc jdbc:mysql://localhost:3306/product từ trái sang phải. jdbc:mysql: cho biết JDBC driver MySQL có thể xử lý URL này. localhost:3306 là nơi driver mở kết nối. product là database được chọn mặc định. Username và password đến từ hai thuộc tính riêng.

DataSource cung cấp kết nối cho hạ tầng truy cập dữ liệu. Trong demo, HikariCP quản lý nhóm kết nối có thể tái sử dụng. Khi Hibernate truy vấn, nó lấy kết nối từ datasource, thực hiện công việc qua JDBC rồi trả kết nối về pool. Mỗi HTTP request có thể dùng lại kết nối đang có.

Biểu thức ${DB_URL:jdbc:mysql://localhost:3306/product} dùng giá trị DB_URL khi biến đã có, hoặc dùng URL sau dấu hai chấm làm mặc định. Ví dụ dưới đây giả sử MySQL dùng 3310, còn web server dùng 812. Khởi động lại ứng dụng sau khi đổi biến.

Với ddl-auto: validate, schema thực tế cần khớp với mapping Hibernate. Nếu thiếu bảng hoặc kiểu cột sai, ứng dụng có thể dừng khi khởi động. update cho phép Hibernate thử sửa schema. create có thể xóa dữ liệu khi tạo lại schema. Demo dùng script SQL làm nguồn tạo bảng và dùng Hibernate để kiểm tra.

Đúng cổng HTTP, sai DB

API đã nghe ở 811 nhưng truy vấn báo table not found. IDE thấy bảng trong schema product. Đề xuất cách khoanh nguyên nhân mà không đổi cổng server.
