Khởi tạo Spring Boot

18:13

Buổi học đặt REST API ở phía backend Java. Client gửi request, backend truy vấn dữ liệu và trả response. Spring Boot hỗ trợ khởi tạo dự án Spring bằng starter và cấu hình tự động dựa trên các thư viện có trong dự án. Ví dụ, có Spring Web thì ứng dụng có thể mở web server nhúng. Có Spring Data JPA và JDBC driver thì ứng dụng cần cấu hình kết nối database tương ứng.

Kết nối MySQL

46:51

Khi ứng dụng có JPA và cần dùng MySQL, Spring Boot phải tạo DataSource để Hibernate lấy kết nối. Nếu thiếu JDBC URL và không có CSDL nhúng phù hợp trên classpath, bạn có thể gặp Failed to configure a DataSource ngay lúc khởi động. Để kết nối MySQL, cần MySQL Connector/J, JDBC URL chỉ tới schema đích và tài khoản được cấp quyền.

Tạo schema và bảng

Dùng IntelliJ Database, MySQL CLI hoặc Workbench để chạy SQL tạo bảng và kiểm tra dữ liệu. Kết nối thử thành công trong IDE chỉ xác nhận thông số của IDE. Spring Boot dùng cấu hình spring.datasource riêng, nên cần kiểm tra hai bên cùng trỏ tới đúng schema. 54:14

Schema của ví dụ là product. Bảng product_offerings dùng id làm khóa chính tự tăng, name bắt buộc, price lưu số nguyên VNĐ và color lưu tên màu. Demo dùng BIGINT để khớp Long trong entity.

Cấu hình datasource và cổng HTTP

Spring Boot đọc application.yaml hoặc application.properties từ src/main/resources. Hai định dạng biểu diễn cùng bộ thuộc tính. YAML nhóm theo cấp, còn Properties dùng khóa như spring.datasource.url. Căn lề YAML bằng dấu cách. 47:38

localhost:3306 là địa chỉ MySQL trong URL JDBC. localhost:811 là địa chỉ HTTP của demo. Spring Boot thường dùng 8080 khi để cổng mặc định. Nếu 8080 đang bị chiếm, đặt server.port: 811 và đổi URL gọi API sang cổng mới. Khi chạy MySQL cổng khác, sửa DB_URL theo đúng cổng. 1:13:16

Demo dùng ddl-auto: validate để kiểm tra bảng đã chuẩn bị sẵn. Chạy SQL khởi tạo trước khi khởi động ứng dụng.

Nếu log báo không nạp được driver class, mở pom.xml và kiểm tra MySQL Connector/J đã có trong classpath sau khi Maven tải dependencies. Với URL jdbc:mysql:, Spring Boot có thể suy ra driver từ URL khi connector đã có sẵn. 1:10:15

JDBC URL, driver và connection pool

Đọc jdbc:mysql://localhost:3306/product từ trái sang phải. jdbc:mysql: cho biết JDBC driver MySQL có thể xử lý URL này. localhost:3306 là nơi driver mở kết nối. product là database được chọn mặc định. Username và password đến từ hai thuộc tính riêng.

DataSource cung cấp kết nối cho hạ tầng truy cập dữ liệu. Trong demo, HikariCP quản lý nhóm kết nối có thể tái sử dụng. Khi Hibernate truy vấn, nó lấy kết nối từ datasource, thực hiện công việc qua JDBC rồi trả kết nối về pool. Mỗi HTTP request có thể dùng lại kết nối đang có.

Biểu thức ${DB_URL:jdbc:mysql://localhost:3306/product} dùng giá trị DB_URL khi biến đã có, hoặc dùng URL sau dấu hai chấm làm mặc định. Ví dụ dưới đây giả sử MySQL dùng 3310, còn web server dùng 812. Khởi động lại ứng dụng sau khi đổi biến.

Với ddl-auto: validate, schema thực tế cần khớp với mapping Hibernate. Nếu thiếu bảng hoặc kiểu cột sai, ứng dụng có thể dừng khi khởi động. update cho phép Hibernate thử sửa schema. create có thể xóa dữ liệu khi tạo lại schema. Demo dùng script SQL làm nguồn tạo bảng và dùng Hibernate để kiểm tra.

Ánh xạ entity

1:36:15

Entity biểu diễn một đối tượng có định danh trong JPA. Hibernate liên kết đối tượng ProductOffering với một dòng của bảng product_offerings. @Entity đánh dấu class, @Table chỉ bảng, @Id chỉ khóa chính và @Column khai báo tên hoặc ràng buộc của cột. 1:41:53

  • Demo khai báo IDENTITY để MySQL sinh khóa từ AUTO_INCREMENT khi ghi một entity mới. Khi đọc, Hibernate lấy giá trị ID từ dòng có sẵn.
  • Integer giữ được null nếu cơ sở dữ liệu chưa có giá. int chỉ biểu diễn số nguyên. Tương tự, Long có thể để trống trước lúc lưu entity mới.
  • Khai báo @Column(name = "tên_cột") khi cần ánh xạ sang tên khác. Ví dụ trường Java displayName có thể ánh xạ tới cột name.
  • JPA cần constructor không tham số public hoặc protected để tạo entity. Ví dụ dùng @NoArgsConstructor. Các annotation Lombok sinh constructor, getter và setter cần thiết khi biên dịch. 1:45:04

Xem entity đầy đủ

Serializable đánh dấu kiểu có thể dùng với cơ chế tuần tự hóa đối tượng của Java. Hibernate ánh xạ entity với dữ liệu JDBC, còn Jackson dựng JSON từ các thuộc tính Java. Hai thao tác trong demo không yêu cầu entity khai báo Serializable.

Vì sao bỏ getter mà vẫn đọc được dữ liệu?

Demo đặt @Id trực tiếp trên trường id và dùng field access. Hibernate có thể đọc và ghi trường đã ánh xạ để dựng đối tượng. Jackson khám phá thuộc tính JSON theo quy tắc riêng. Ở class này, getter public do Lombok sinh giúp Jackson nhìn thấy các trường private. Vì vậy truy vấn database có thể thành công trong khi response JSON lỗi hoặc thiếu trường.

Dòng có price = NULL là một sản phẩm đã được tìm thấy với giá chưa xác định. Repository trả Optional.empty() khi không có dòng ứng với ID. Thử thêm một dòng bằng tài khoản có quyền ghi rồi lấy ID đã sinh trên cùng kết nối MySQL.

Gọi /products/{id} với ID vừa sinh. Kỳ vọng nhận 200 và "price": null. H2 test trong dự án kiểm tra đúng trường hợp này với một dòng mẫu có cả giá và màu để trống.

Repository và service

1:57:39

Repository đọc theo khóa chính

JpaRepository<ProductOffering, Long> khai báo kiểu entity và kiểu ID. Spring Data tạo implementation cho interface lúc chạy, nên có thể gọi ngay findById. Ví dụ truy vấn theo khóa chính tận dụng phương thức có sẵn. 1:58:33

Service xử lý kết quả truy vấn

Khi nhận ID 1, controller gọi interface service. Lớp triển khai có @Service được Spring đăng ký để controller có thể nhận qua constructor. Service gọi repository.findById(1L). Khi repository trả Optional.empty(), service chuyển kết quả đó thành lỗi không tìm thấy sản phẩm. 2:08:12

orElseThrow trả entity khi có dữ liệu và tạo exception đã chỉ định khi Optional rỗng. Nếu viết bằng isEmpty() và get(), phải kiểm tra nhánh rỗng trước. Service nhận repository qua constructor. Spring tự chọn constructor khi bean chỉ khai báo một constructor. 2:11:22

Repository đầy đủ Service đầy đủ

Spring cung cấp implementation bằng cách nào?

Khi khởi động, Spring Data tìm interface repository rồi tạo một bean qua proxy. Spring truyền bean này vào constructor của service. Khi tạo controller, Spring tìm bean phù hợp với kiểu ProductOfferingService và truyền vào constructor của controller. Mỗi kiểu ở demo có một bean phù hợp, và mỗi class chỉ có một constructor nên Spring tự dùng constructor đó.

findById là phương thức có sẵn để tra khóa chính. Để tra theo màu, khai báo phương thức dưới đây trong repository. Spring Data suy ra điều kiện từ thuộc tính Java color. Kiểu List phù hợp vì một màu có thể có nhiều sản phẩm. Kết quả là danh sách rỗng khi không có bản ghi phù hợp.

Trong luồng theo ID, repository cung cấp trạng thái có hoặc không có bản ghi. Service quyết định việc thiếu sản phẩm có nghĩa gì với tác vụ hiện tại. Với orElseThrow(() -> ...), hàm tạo exception chỉ chạy khi Optional rỗng. Controller và Spring MVC quyết định cách thể hiện kết quả đó bằng HTTP.

Mở API REST

2:28:43

Controller tiếp nhận HTTP request, gọi service và trả về HTTP response. @RestController đánh dấu controller trả dữ liệu trực tiếp. @GetMapping ghép phương thức GET với đường dẫn. ResponseEntity.ok(product) đặt mã 200 và đưa sản phẩm vào body để Spring chuyển sang JSON.

Đặt ID trong URI để mỗi sản phẩm có địa chỉ riêng. GET /products/1 và GET /products/2 dùng cùng handler. Spring MVC lấy phần {id} và chuyển sang kiểu Long trước khi gọi service. 2:40:18

Với GET /products/1, Spring tách chuỗi 1 từ URL rồi chuyển thành Long. Nếu service ném ProductOfferingNotFoundException, @ResponseStatus(HttpStatus.NOT_FOUND) trên exception cho Spring biết cần trả về 404. Với /products/abc, việc đổi sang Long thất bại và Spring trả 400 trước khi service chạy.

Lần theo một request từ URL đến JSON

  1. HTTP tới ứng dụng. Trình duyệt gửi GET /products/1 đến cổng 811. Servlet container nhúng nhận request và chuyển cho DispatcherServlet của Spring MVC.
  2. Chọn handler. Spring ghép /products trên class với /{id} trên method. Nó chọn method cho GET, lấy đoạn 1 và chuyển kiểu trước khi gọi Java method.
  3. Đọc dữ liệu. Controller gọi service.getById(1L). Repository dùng JPA, Hibernate gửi truy vấn với ID đã gắn vào tham số qua JDBC. SQL bên dưới mô tả điều kiện truy vấn. Alias và danh sách cột sinh ra thực tế có thể khác.
  4. Ghi response. Hibernate dựng ProductOffering từ dòng MySQL trả về, service lấy entity từ Optional, controller đưa đối tượng vào body của ResponseEntity. Spring MVC chọn bộ chuyển đổi và Jackson ghi JSON với kiểu nội dung application/json.

/products/1 đặt định danh tài nguyên trong path. Trong ví dụ lọc /products?color=red, color là query parameter và có thể nhận bằng @RequestParam. Demo hiện thực route lấy chi tiết. Route lọc minh họa cách truyền đầu vào cho API danh sách.

Dừng ở biên đầu tiên bị hỏng

  1. Chưa có HTTP response. Kiểm tra log xem Tomcat đã khởi động chưa. Nếu app dừng trước bước đó, tìm nguyên nhân gốc, chẳng hạn lỗi kết nối MySQL hoặc thiếu bảng.

Chạy demo trên máy

Demo dùng Spring Boot 3.5.10, mã nguồn tương thích Java 17 và chạy với Maven. Các câu lệnh dưới đây dùng PowerShell và MySQL cục bộ. Chi tiết tạo tài khoản và dữ liệu có trong README.

  1. Tạo database product và tài khoản MySQL có quyền đọc schema đó.
  2. Chạy demo/src/main/resources/schema.sql rồi demo/src/main/resources/data.sql trong schema product bằng tài khoản có quyền ghi.
  3. Từ thư mục chứa trang này, chạy demo và gọi API ở cửa sổ PowerShell khác.

Dùng mvn -f demo/pom.xml test để chạy bộ kiểm thử với H2 trong bộ nhớ. Bộ kiểm thử xác nhận JSON, ID không tồn tại, ID sai kiểu và trường số hoặc màu có thể rỗng. Khi thực hành MySQL, đối chiếu mã phản hồi và body với ví dụ trên.

Tự kiểm tra và giải thích kết quả

1. Cơ sở dữ liệu có dòng với giá NULL. API trả gì?

Kỳ vọng 200 và "price": null. Dòng tồn tại, Optional chứa entity và trường Integer price nhận được null. Thử thêm dòng rồi gọi đúng ID để kiểm chứng.

2. Vì sao /products/abc khác /products/999?

abc khiến Spring MVC thất bại khi đổi kiểu sang Long. Với 999, đổi kiểu thành công. Nếu thiếu dòng, repository trả rỗng và exception trong demo được ánh xạ thành 404.

3. Đổi cổng HTTP có cần sửa JDBC URL?

Chỉ đặt SERVER_PORT=812, khởi động lại và gọi http://localhost:812/products/1. URL JDBC vẫn dùng cổng MySQL. Hai tiến trình mở hai điểm kết nối riêng.

4. Vì sao IDE đọc được bảng mà ứng dụng vẫn không kết nối được?

IDE và ứng dụng có cấu hình riêng. So sánh DB_URL, user, quyền và schema mà ứng dụng đọc. Nếu log không tìm thấy driver, kiểm tra Maven và classpath của ứng dụng.

5. Dữ liệu có trong debugger mà JSON thiếu trường thì xem ở đâu?

Kiểm tra getter public của entity và annotation processing. Thử viết getName() bằng tay trong một bản thử, build lại rồi quan sát trường name. Hibernate dùng field access nên vẫn có thể đọc dữ liệu ở bước trước đó.
