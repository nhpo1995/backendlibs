Mục tiêu của Buổi 3

Viết được API tạo mới và cập nhật theo ID, giải thích cách Spring Data xác định entity mới, và chọn cách lưu enum phù hợp với schema.

Cần biết Java interface, SQL INSERT và UPDATE, cùng luồng controller, service, repository. Ôn Buổi 2.

Demo dùng H2. POST nhận thông tin sản phẩm mới và trả 201 cùng ID được sinh. PUT dùng ID trong URL để cập nhật đúng một sản phẩm đã có, hoặc trả 404 nếu không tìm thấy.

POST, save và định danh

17:28 ↗

Khi client gửi tên, giá và màu cho POST, controller nhận dữ liệu, service tạo entity và yêu cầu repository lưu. Sau đó có thể gọi GET bằng ID trả về để xác nhận bản ghi đã được lưu. @RequestBody chuyển JSON sang kiểu Java. Service chuẩn bị entity, repository chuyển thao tác ghi cho EntityManager. Kết quả của save là đối tượng cần dùng để dựng HTTP response.

Mặc định, Spring Data JPA dùng @Version kiểu wrapper nếu có, rồi mới đến ID khi entity không có version phù hợp. Demo không có @Version. Entity có ID null được coi là mới và đi qua persist. ID đã gán thường đi qua merge theo quy tắc này. merge chép trạng thái vào một instance được quản lý và trả instance đó. Câu SQL cụ thể còn tùy trạng thái entity, bộ sinh ID và dữ liệu đang có.

Giả sử API tạo mới nhận thẳng entity và dùng save. Nếu client gán ID của bản ghi đang tồn tại, Spring Data JPA có thể chọn merge và cập nhật bản ghi đó. Hãy dùng DTO chỉ nhận các trường được phép ghi. Nếu ID để trống mà mapping vẫn yêu cầu gán thủ công, Hibernate sẽ báo lỗi khi persist. Cột tự tăng trong DB và cấu hình IDENTITY cần đi cùng nhau để Hibernate làm INSERT và nhận lại ID. Demo dựng entity từ DTO có các trường được phép sửa nên một giá trị id gửi thêm không thể điều khiển ID. 36:09 ↗ 40:59 ↗ 43:51 ↗

SEQUENCE lấy giá trị từ sequence của DB. TABLE dùng bảng cấp số. UUID tạo UUID, còn AUTO để provider chọn theo loại ID và nền tảng. Mỗi cách cần schema tương ứng. Xem entity.

Map enum và đồng bộ schema

1:17:05 ↗

Với kiểu Java Status, chỉ có hai giá trị ACTIVE và INACTIVE. Jackson mặc định chuyển chuỗi JSON theo tên hằng enum. Nếu gửi ARCHIVED, request demo lỗi trong bước đọc body và trả 400 trước khi gọi service.

STRING lưu tên hằng, còn ORDINAL lưu vị trí bắt đầu từ 0. Việc chèn hoặc đổi thứ tự enum làm đổi ý nghĩa dữ liệu cũ khi dùng ordinal. Khi đổi tên hằng lưu dạng chuỗi, cần migration dữ liệu. Ví dụ, ORDINAL bind giá trị số trong khi schema có thể yêu cầu giá trị chuỗi. Khi ghi lỗi hoặc đọc ra trạng thái sai, đối chiếu kiểu bind và DDL. JSON hợp lệ chỉ xác nhận bước đọc request, chưa xác nhận mapping xuống CSDL. Demo dùng cột VARCHAR(8) có CHECK để kiểm tra hai giá trị hợp lệ ở DB. 1:35:00 ↗ 1:38:41 ↗

PUT theo ID và dirty checking

2:30:43 ↗

Với PUT /buoi-03/products/1, URI xác định sản phẩm số 1 và body cung cấp tên, giá, màu, trạng thái mới. Service tìm entity theo ID trong transaction rồi sửa bốn thuộc tính. Hibernate theo dõi thay đổi của entity đang được quản lý và flush khi commit. Nếu ID vắng, service trả 404 trước khi cập nhật.

Demo dùng khóa ghi khi đọc bản ghi để đồng bộ với API gán ở Buổi 6. Với PUT ở đây, client gửi đầy đủ tên, giá, màu và trạng thái. Gửi lại cùng dữ liệu đưa resource về cùng trạng thái. POST tạo ID mới cho mỗi lần tạo hợp lệ. Giá trị ID gửi dư trong body không ảnh hưởng đến bản ghi đích. 2:54:46 ↗ 3:16:00 ↗

Chạy từng dòng dưới đây trong cửa sổ PowerShell thứ hai trên dữ liệu vừa khởi động. Invoke-RestMethod hiển thị body thành đối tượng. Dùng -StatusCodeVariable với PowerShell 7 nếu muốn in status của lệnh thành công.

Kỳ vọng POST trả 201 và ID 3 khi đây là lần tạo đầu. PUT trả 200, đúng ID vừa tạo và giá 135000. Sản phẩm 2 vẫn có giá 150000. Đổi URL thành ID 999 để quan sát 404. Với ID hợp lệ, lần lượt thử status: "ARCHIVED", status: 0 hoặc price: 135000.9. Cả ba trả 400 ở bước đọc JSON. Gọi GET bằng ID vừa tạo để xác nhận bản ghi giữ giá trị của lần cập nhật thành công.

@Enumerated điều khiển cách JPA ghi trạng thái xuống DB. Jackson xử lý định dạng của trạng thái trong JSON. Demo bật fail-on-numbers-for-enums và tắt accept-float-as-int để từ chối số dùng làm thứ tự enum và số thập phân truyền vào trường Long.

Để tái hiện lỗi thiếu bộ sinh ID, sao chép demo, bỏ @GeneratedValue trong ProductOffering, khởi động lại rồi gọi POST. Tìm lỗi ID phải được gán trước khi persist. Khôi phục annotation và chạy lại cùng request để thấy INSERT nhận ID do DB tạo.

Tự kiểm tra

1. Vì sao có cột tự tăng mà bỏ @GeneratedValue vẫn lỗi?

Provider cần biết ID do DB sinh. Với mapping ID gán thủ công, entity mới có ID null không đáp ứng hợp đồng persist.

2. PUT /3 mang id=2 trong body sửa bản ghi nào?

Bản ghi 3. Controller lấy ID từ URL, DTO chỉ chuyển các trường nghiệp vụ và service lấy đúng entity theo ID.

3. Đổi thứ tự hằng enum ảnh hưởng kiểu lưu nào?

ORDINAL phụ thuộc thứ tự khai báo. STRING vẫn đọc được nếu tên hằng giữ nguyên.

4. Vì sao sửa thuộc tính trong update mà không gọi save vẫn ghi xuống?

Entity được load trong transaction và còn managed. Hibernate phát hiện thay đổi khi flush.

5. PUT ID vắng sẽ tạo sản phẩm mới trong demo chứ?

API này xác định cập nhật bản ghi có sẵn. ID vắng dẫn đến 404 trước bước ghi.
