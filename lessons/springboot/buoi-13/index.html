DTO là hợp đồng, projection là cách lấy dữ liệu

Ứng dụng có entity Product với id, name, price, color, status. Danh sách chọn sản phẩm chỉ cần id và name, ví dụ {"id":1,"name":"Mouse"}. Nếu trả entity, việc thêm thuộc tính lưu trữ hay quan hệ lazy có thể thay đổi JSON hoặc kích hoạt truy vấn ngoài ý muốn. Chọn rõ DTO cho từng use case: DTO nhập chứa trường người gọi được phép gửi; DTO trả về chứa trường client cần biết.

Summary có constructor đúng thứ tự và kiểu vì là record. Cách ModelMapper dùng JavaBean có constructor không tham số và setter tương ứng, ví dụ setName(String name). STRICT giảm khớp nhầm, nhưng không đảm bảo DTO mới có dữ liệu đúng. Nếu đổi destination từ name sang label, thêm mapper.typeMap(Product.class, NamedView.class).addMapping(Product::getName, NamedView::setLabel) (với DTO có setter tương ứng), rồi kiểm tra giá trị và kiểu. Không tự map toàn bộ request nhạy cảm sang entity; set rõ những trường được phép đổi.

Bộ lọc thay đổi theo tham số

Client truyền name=lap&minPrice=200&maxPrice=350&color=BLACK&status=ACTIVE. Tên khớp Laptop (300) và Laptop Stand (200); cả hai qua khoảng giá và màu; Laptop Stand bị loại vì INACTIVE. Kết quả duy nhất ID 3. Nếu bỏ status thì có [3,4] theo ID. Không truyền giá có nghĩa là bỏ qua điều kiện; dùng Long thay vì long để phân biệt vắng tham số và giá bằng 0.

Specification<Product> là đối tượng có thể sinh Predicate khi Spring Data cung cấp Root, CriteriaQuery và CriteriaBuilder. cb.conjunction() là điều kiện đúng khi chưa có bộ lọc. and() tạo specification mới; phải gán lại. findAll(spec, pageable) áp dụng điều kiện cho kết quả phân trang và truy vấn đếm nếu cần. Đừng thêm fetch join tùy tiện vào spec dùng cho COUNT; nếu join to-many làm trùng root, kiểm tra cả tổng, danh sách và cách đếm riêng.

Binding và quy tắc lọc

@ModelAttribute ProductFilter filter giúp MVC bind query string vào record theo tên component. minPrice=abc sai kiểu trước khi chạy query; minPrice=350&maxPrice=200 có đúng kiểu nhưng sai quy tắc, trả 400 do kiểm tra logic. Màu và trạng thái nhận enum, demo dùng chính xác BLACK / WHITE và ACTIVE / INACTIVE. Vì nameContains escape wildcard, name=%25 tìm ký tự phần trăm thật.

So với nhiều đoạn if thêm trực tiếp vào Criteria (Buổi 7), Specification gom điều kiện tái sử dụng cùng một interface; SQL cuối vẫn do JPA dựng. Nếu thêm tham số màu mà không thấy kết quả thay đổi, xác minh URL bind đúng tên, kiểm tra logic có gán spec = spec.and(...), rồi đọc SQL. Nếu truy vấn chỉ có một điều kiện cố định, derived query hoặc @Query có thể dễ đọc hơn.

Thực hành và gỡ lỗi

Trong thư mục demo chung, chạy bằng JDK 17 trở lên và Maven. Các lệnh HTTP dùng PowerShell 7. H2 được nạp dữ liệu mẫu mỗi khi khởi động lại. Nếu thực hành theo thứ tự, hãy khởi động lại trước khi cần dùng dữ liệu gốc.

Hai lệnh đầu trả sáu object giống nhau, mỗi object chỉ có ID và name. So log SQL: projection chỉ select ID và tên; mapper gọi truy vấn đọc entity đủ thuộc tính rồi thu nhỏ JSON. Lệnh thứ ba có ID 3; lệnh thứ tư có ID 3 và 4; lệnh cuối 400. Thêm size=1&page=2 vào lệnh thứ tư, kết quả có riêng ID 4 và totalElements:2.

Trên bản sao, bỏ phép gán ở nhánh status, chỉ gọi spec.and(...) rồi bỏ kết quả. Chạy lại lệnh có status=ACTIVE. ID 4 lọt vào; log SQL thiếu predicate status. Khôi phục phép gán, build và kiểm tra chỉ còn ID 3. Một lỗi khác là dùng root.get("product_status") thay cho tên thuộc tính status; Criteria dùng tên thuộc tính Java.

Mã để đối chiếu: Products.java · LabApplication.java · dữ liệu mẫu · kiểm tra HTTP.

Tự kiểm tra

DTO nhỏ hơn entity có tự giảm cột SELECT không?

Không. Mapper Java chạy sau SELECT. Dùng projection ngay trong truy vấn để giảm cột.

Vì sao không dùng long cho giá tùy chọn?

Giá trị mặc định 0 khiến khó phân biệt vắng tham số và yêu cầu lọc giá 0.

AND khác gì OR trong bộ lọc ví dụ?

AND bắt buộc thỏa tất cả điều kiện. OR có thể trả cả sản phẩm khác tên nhưng thỏa giá hoặc màu.

Giá min 350, max 200 nên trả [] hay báo lỗi?

Hợp đồng demo trả 400 vì khoảng giá do client gửi không hợp lệ.

spec.and(...) có đổi object spec gốc không?

Không. Giữ kết quả trả về để dùng điều kiện vừa ghép.

Làm sao biết mapper map sai hay truy vấn lọc sai?

Đối chiếu các hàng và cột trong SQL/giá trị entity trước, rồi so DTO và JSON.
